🎓 Viva & Project Presentation Master Cheatsheet

Examiner Ready

1. 4-Step System Workflow (Input → Process → Database → Output)

Step 1: QR ID Generation
Encoding: Student details convert into a 2D matrix barcode using Python's qrcode with Reed-Solomon Error Correction Level H (30% damage recovery).
Step 2: Real-Time Scanning
Decoding: OpenCV detects the three square Finder Patterns (1:1:3:1:1 ratio) to compute perspective warp and extract the string payload instantly.
Step 3: DBMS Validation
Composite SQL Check: Runs SELECT * WHERE roll_no = ? AND scan_date = CURRENT_DATE to block duplicate proxy scans.
Step 4: Output & Reports
Reporting: Real-time analytics counters, student present/absent roster, and 1-click export to CSV and Excel (`.xlsx`).

2. Normalized ER Schema (2 Relational Tables)

TABLE 1: students (Master Entity)

  • • roll_no TEXT PRIMARY KEY (e.g. CSE-2026-042)
  • • full_name TEXT NOT NULL
  • • branch TEXT NOT NULL
  • • semester TEXT NOT NULL
  • • qr_path TEXT
  • • created_at TEXT DEFAULT NOW

TABLE 2: attendance_logs (Transaction Entity)

  • • log_id INTEGER PRIMARY KEY AUTOINCREMENT
  • • roll_no TEXT (FK → students.roll_no)
  • • scan_date TEXT NOT NULL (YYYY-MM-DD)
  • • check_in_time TEXT NOT NULL (HH:MM:SS AM/PM)
  • • status TEXT DEFAULT 'Present'
  • • entry_type TEXT (Classroom vs Library)

3. Top Viva Questions & Examiner-Ready Answers

Q1: How does your system stop a student from scanning their QR code 5 times in a row?
Answer: We apply a composite uniqueness check in SQL: SELECT * FROM attendance_logs WHERE roll_no = ? AND scan_date = CURRENT_DATE AND entry_type = ?. If a row already exists for that student on that date, the application flags it as a duplicate, plays an audible alert, and displays an "Already Marked Present" notification with their original check-in timestamp instead of inserting a duplicate row.
Q2: Why did you choose SQLite instead of MySQL or MongoDB for this microproject?
Answer: SQLite is a serverless, ACID-compliant relational database built directly into Python's standard library (sqlite3). It requires zero background server daemon setup, zero configuration, and stores the entire database in a single portable attendance.db file, making it ideal for standalone college lab deployment.
Q3: How does OpenCV recognize a QR code even if the card is slightly tilted?
Answer: Every QR code contains three large square Finder Patterns in its corners. OpenCV's QRCodeDetector searches for the specific ratio of black-to-white pixels (1:1:3:1:1) within those squares. Once detected, it calculates the geometric perspective transformation (homography matrix) to rectify the tilt before reading the data bits.
